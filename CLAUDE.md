# tradedesk

Short-term momentum scanner for NSE stocks using the INDstocks (INDmoney) API.
Evening scan on daily charts, live trigger monitoring, trades held hours to 10 sessions.
It alerts; the human places every order.

## Hard rules
- NEVER call or implement order placement, modification or cancellation unless the task explicitly says "Milestone M12".
- The API reference is docs/indstocks-api.md. Never guess endpoints, fields, formats or limits; read the doc.
- Every INDstocks call goes through broker/indstocks/ratelimit.py. Never exceed documented limits.
- NEVER hardcode tokens or the TOTP secret. Tokens live in memory; the TOTP secret comes from keyring.
- The live scanner and the backtester share engine/engine.py. No live-only or backtest-only signal logic.
- Fills are gap-aware everywhere: an open beyond a stop or trigger fills at the open.
- Overnight positions are long-only.
- No feature, signal or label may use data from after its timestamp. Every setup and feature has a look-ahead or leakage test.
- Portfolio limits (heat, positions, sector caps, daily and weekly limits) apply in backtests, paper book and live alike.
- Fail closed: stale data, a disconnected feed or API errors pause alerts and raise a health alert.
- Never block the asyncio event loop; CPU-heavy work runs in a worker thread.
- Timezone is Asia/Kolkata. Candle logic uses exchange timestamps, not the local clock.
- Claude output is advisory text only; it can never create a signal or change a price, level or quantity.
- The prediction layer can only lower grades or size, never raise size beyond config caps.
- Changes under engine/, setups/, live/ or data/ must pass tests/replay and tests/gaps.

## Conventions
- Money and rates are `Decimal`, never float. Config percentages are fractions (0.001 = 0.1%).
- Cost lines are rounded half-up to the paisa individually before summing; STT and stamp duty are rounded to the nearest RUPEE per trade (ledger-verified: Rs 0.86 STT -> 1, Rs 0.13 stamp -> 0). GST = 18% x (brokerage + exchange txn + SEBI) - not IPFT/STT/stamp. Brokerage = 0.1% capped at Rs 5 with a Rs 2 minimum (Muhurat reversal 2.36 = 2 + GST).
- Net R:R = (gross reward − costs to target) / (gross risk + costs to stop). A stop-out loses more than 1R. PLAN.md §7's worked numbers (1.4R/2.3R, ~₹110) assume ₹20/order; INDmoney actually charges 0.1% capped at ₹5 (min ₹2) per order, so the same card is ₹72 and 1.61R/2.48R.
- The cost calculator never infers intraday vs delivery; the caller passes `TradeType`. Same-day buy+sell is INTRADAY.
- Charge rates live in config/risk.yaml under `costs:`. Real contract-note figures live in tests/golden/contract_notes.yaml; if INDmoney changes pricing, update both.
- tests/golden/rate_card_examples.yaml + test_rate_card.py are a PROVISIONAL stand-in for the missing intraday golden notes: hand-computed from the documented rate card, not a real bill. They are never the M1 done-when count (test_golden_coverage_report reads contract_notes.yaml only) - delete rate_card_examples.yaml once a real intraday note lands there.
- INDstocks facts baked into broker/indstocks/: REST codes are `NSE_3045`, WebSocket codes `NSE:3045`; candle `ts` is the OPEN time in epoch seconds, requests use epoch ms; ≤5 codes per candle call, ≤1000 per quote call, ≤3000 instruments per WS connection; one TOTP token live at a time (24 h, 1 generation/min).
- The doc's FAQ section contradicts the endpoint pages (different WS URL, `symbols` param). Follow the endpoint pages and the OpenAPI spec, never the FAQ.
- Market-data prices are float (pandas/DuckDB bound); accounting money is Decimal.
- Indicators (engine/indicators.py) are hand-written pandas with TradingView conventions (ema seeded on first value; rma = Wilder, SMA-seeded, na until n finite values; population stdev). No TA-Lib: its C DLL would hit Smart App Control.
- Pattern detectors (engine/patterns.py) evaluate the LAST bar of the frame they receive and return geometry models; look-ahead freedom comes from slicing the frame to the evaluation date. Pivots carry `confirmed_at`.
- tests/engine/test_indicators.py::test_daily_features_have_no_look_ahead is the leakage test for every feature column; extend `daily_features` and it is covered automatically.
- engine/engine.py::scan_day is THE scan. The backtester (backtest/runner.py) calls it with frames sliced to each session; the live evening scan (M6) calls it with today's frames. Never add signal logic anywhere else.
- Entry confirmation is live/confirmation.py::confirm_trigger (15-minute CLOSE above the level; the 09:15 bar never triggers; bars starting >= 15:00 defer to the daily close; optional volume-vs-slot-norm). The live monitor and the backtester both call it; the backtester uses it whenever 15-minute candles are in the store, else falls back to daily bars (open beyond trigger+1 ATR = chased; open past the stop = out at the open; a bar touching both stop and target = stop). Exits are daily-bar in the backtester either way.
- live/trigger_monitor.py fails closed: no ticks for 120 s pauses alerts (DATA STALE); alerts raised while paused are delivered marked [delayed] on resume; after a WebSocket reconnect `resync()` checks triggers/stops against REST day high/low before alerts resume.
- tests/live/test_live.py::test_replay_matches_backtester_triggers is the M7 parity test (same 15-minute bars as ticks -> same triggered ids and fill prices).
- Alerts (M8): alerts/router.py routes by the entry's grade (A -> desktop+Telegram+dashboard, B -> dashboard, C -> log only) or by level for non-signal alerts; Telegram sends are queued and drained by AlertRouter.worker so the monitor never blocks. - The INDstocks feed ALREADY serves split/bonus-adjusted daily history (verified 2026-09-12 against 40 real NSE corporate actions: 39 smooth across the ex-date). So `CandleStore` defaults to `apply_corporate_actions=False` and `load(adjusted=True)` does NOT rescale. Applying factors on top double-adjusts and silently corrupts history (NESTLEIND's 1:10 split turned Rs 1,361 into Rs 68). The corporate_actions table is still imported - it drives the `suspected_unadjusted_split` detector and audit - just not applied. Only pass `apply_corporate_actions=True` for a feed that genuinely serves unadjusted prices. Never write adjusted prices back.
- `suspected_unadjusted_split` in the quality report is a RATIO HEURISTIC, not evidence: it matches any close/prev_close near a known split/bonus factor, so rights issues and genuine crashes trip it (e.g. BALKRISHNA 2024-03-07 was a rights issue at a deep discount, not a bonus). Always confirm against the corporate_actions table before acting on one.

- Prediction layer (M11) lives in prediction/: labeling.py (triple barrier: T1 -> 1, stop or gap-through-stop -> 0, vertical barrier max_hold -> 0; a bar touching both = stop, as in the backtester), features.py (31 features, all known at the arming close; tests assert a truncated frame gives identical features), train.py (build_dataset from a BacktestResult, purged walk-forward BY DATE with ml.yaml embargo_sessions, sigmoid-calibrated logistic baseline; LightGBM only if importable AND better OOS Brier - it is NOT installed here, Smart App Control), predict.py (apply_probability can only LOWER a grade or halve qty, gated by ml.yaml enabled+not shadow; shadow mode only appends a score note and logs), calibration.py (drift_check pauses the layer when a bucket with >= 30 resolved signals drifts > 0.15). `tradedesk train` refuses --no-shadow; switching on is a config edit, never a CLI flag.
- M13 (crypto): markets/ has the one real cross-market abstraction, CostModel (NSE's statutory cost shape - STT/stamp/GST/DP/SEBI - has no crypto equivalent; EquityCostModel is a thin wrapper over risk/costs.py, proven byte-identical by property tests). Deliberately NOT built as classes: CalendarProvider/RegimeProvider - data/universe.py::trading_days and engine/regime.py::classify_regime were already market-agnostic (a reference code, an optional VIX series), so wrapping them would be speculative before a second market needed them differently. broker/coindcx/ is read-only, public endpoints, no key: CRITICAL quirk - CoinDCX's candles endpoint silently ignores startTime/endTime unless BOTH are passed together (passing one returns the latest bars regardless, no error) - see broker/coindcx/models.py. CoinDcxClient.candles_history() takes tradedesk scrip codes ("CDX_BTCINR"), NOT CoinDCX's own `pair` ("I-BTC_INR") - unlike IndstocksClient, whose scrip_code already is its native id; needs `register_pairs()` (typically from `CandleStore.custom_symbols()`, which reads the `name` column - Instrument.custom_symbol's storage slot) before use, or every call 422s (a real bug this exact way, found only by actually running `data load --market crypto`, not by mocked tests). data/history_loader.py::load_history takes any MarketDataClient (Protocol) plus max_codes_per_call (CoinDCX: 1 pair/call, no batching) and error_types - defaults preserve NSE behaviour exactly. engine/filters.py::apply_filters takes a CostModel + primitives (min_net_rr, min_avg_daily_turnover_inr, atr_pct_band) instead of RiskConfig/UniverseConfig, so it assumes nothing about which market's config shape it's given; atr_pct_band=None (crypto has no calibrated one yet) skips that check rather than applying NSE's. backtest/portfolio.py::Portfolio.costs and BacktestConfig.costs are CostModel, not ChargeSchedule (None on BacktestConfig -> EquityCostModel(risk.costs), so every existing NSE caller needed zero changes). scan/evening_scan.py's scan_config/build_watchlist/run_evening_scan all take an optional `market: Market` (default NSE, same reasoning). paper/book.py and risk/limits.py stay NSE-only on purpose (crypto has no paper trading or live risk manager yet) - they still build EquityCostModel unconditionally. backtest/runner.py::_dedupe_by_calendar_day guards a real CoinDCX quirk: some 2019-2020 history has a synthetic zero-volume filler bar ~1s before the real bar for that day, which crashes prepare_market's reindex on a duplicate-labeled axis if not deduped (no-op for NSE's clean timestamps). Fractional sizing (2026-09-12): SizeInputs/BacktestConfig/Market carry `qty_step` (1.0 = whole units, the NSE default, so nothing NSE changed - a hypothesis property test asserts step 1.0 reproduces the old math.floor path exactly) and `min_notional`. risk/sizing.py::quantize_qty snaps via Decimal so quantities are clean numbers, not 0.0032200000000000003. Fill.qty/Position.qty_initial/qty_open are float; the partial-exit rule quantizes with ROUND_HALF_EVEN because that is what the old `round()` did at step 1.0. Cost models take `qty: float` and convert with models.py::qty_decimal (str-based - `Decimal * float` raises outright, and `Decimal(0.0032)` expands the binary float). CAVEAT: crypto uses ONE fine step (1e-8) for the whole market, but CoinDCX publishes a step PER PAIR (BTCINR 0.00001 ... DOGEINR 1) plus a per-pair min_quantity - the uniform step moves a quantity by <0.3%, fine for research, NOT sufficient to place a real order. The journal/live NSE path stays whole-unit.
- Health check 2026-09-12 (`data status` staleness line, VIX, stablecoins). Four real defects, all of the same shape - a lookup returned "nothing" and every layer downstream accepted it: (1) **India VIX was never loaded at all.** `data load` appended the benchmark to its targets but not `universe.volatility_index`, AND `CandleStore.scrip_code_for` was case-sensitive while config says "INDIA VIX" and the feed stores "India VIX" - so `cfg.vix_code` was None and engine/regime.py (which takes `vix: pd.Series | None` and degrades quietly) ran WITHOUT its volatility input for the project's whole history. Both fixed; the lookup is now case-insensitive. FOLLOW-UP FIXED SAME DAY: the fail-open this left standing - `vix_calm = vix_last is None or ...` treated a missing reading as calm, so the VIX risk_off trigger could never fire while the data was absent - is now closed by `Market.vix_required` (True for NSE, False for crypto) threaded into `classify_regime(..., vix_required=...)`: when required and missing, the regime now returns RISK_OFF/size 0 with reason "VIX data missing for a market that requires it - failing closed", instead of falling through to a classification that never checked it. `mcp_server.py::analyze` never resolved `cfg.vix_code` either (same bug, different caller) - fixed alongside so it gets a real reading rather than a permanent forced RISK_OFF. (2) **`data load` silently under-fetches.** A run left 739 of 2640 codes (and NIFTY) a session behind with `fetched=0, error=None` - the loader cannot tell "no new bar exists" from "the API returned nothing". Re-running the identical command fetched them all, 0 errors, which is what proves it a fetch gap not missing data. `data load` now does a straggler sweep (retry everything still behind the newest bar, report what remains) and `data status` reports how many codes are BEHIND the newest bar - it previously printed only `max(stamps)`, which hid the gap completely. This supersedes the NIFTY-specific re-fetch workaround in `tradedesk-after-close` (left in place, now redundant). (3) **INR stablecoins polluted the crypto universe.** CDX_USDTINR/CDX_USDCINR are pegged near Rs 98 (2.1% coefficient of variation vs 30-90% for a real coin) so every "breakout" is peg noise - and being the MOST liquid INR pairs, a turnover floor selects FOR them (USDCINR was 51 of 154 signals in the first crypto dataset). `UniverseRules.exclude_codes` (empty for NSE, stablecoins for crypto via `crypto_market.universe.exclude`) drops them in both `universe_on` and `prepare_market`. (4) regime text claimed "VIX calm" for crypto, which has no VIX - now says "no VIX for this market"; and a `size 0:` rejection with no cap fired printed an empty reason, now "risk budget below one qty step".
